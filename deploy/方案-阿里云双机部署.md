# 方案：阿里云双 ECS 部署（2c2g×2）+ 小程序接入 + 自动化发布

- 日期：2026-10-11
- 前提：两台同 VPC 同安全组的 ECS（2c2g）；镜像走阿里云 ACR；域名+备案（生产 HTTPS 必须，见 §4）

## 1. 总体架构：两台各司其职（非主备）

```
微信小程序 / PC
      │  HTTPS 443（生产）或 http://IP（开发态，工具勾"不校验域名"）
      ▼
┌─ ECS-A（入口+状态层）──────────────┐   ┌─ ECS-B（业务层）─────────────┐
│ nginx(TLS) → gateway:8080          │   │ family / health / file /     │
│ member                             │   │ reminder （4 个业务服务）     │
│ mysql(数据卷) redis nacos          │◄──┼── 内网注册/调用 A 的 nacos    │
└────────────────────────────────────┘   └──────────────────────────────┘
        镜像来源：本地 build → 阿里云 ACR → 两台各自 pull
```

内存账（当前已调优后的实测值）：A ≈ mysql155+redis9+nacos368+gateway272+member246
≈ 1.05G；B ≈ 4×250 ≈ 1.0G。2G 机器各留 ~0.8G 余量，可行；再加 swap 1G 兜底。

关键决策：

1. **库表集中在 A**：MySQL/Redis/Nacos 只在 A 跑，B 走内网连接（同 VPC 内网免流+低延迟）。
2. **file 服务存储**：双机后本地磁盘不再共享 → 切 OSS（代码已支持，`FILE_STORAGE_TYPE=oss`），
   或过渡期把 file 服务也放 A（上传文件落 A 数据卷）。M1 先同机过渡，OSS 参数留好。
3. **Nacos 发现跨节点**：B 的服务 `SPRING_CLOUD_NACOS_DISCOVERY_IP` 必须显式配成各自
   内网 IP，否则注册的是容器内网 IP，A 调不通 B。
4. **安全组**：公网只开 80/443（A）+ 22（限自己 IP）；3306/6379/8848/8080 一律不开公网，
   仅同安全组内网互通。

## 2. 部署单元与产物

```
star-site-backend/deploy/
  docker-compose.prod.yml   # 以 profile=node-a / node-b 区分两台的服务集
  nginx/star-site.conf      # A 上的 TLS 终结 + /api 反代 gateway
  release.sh                # 本地：build → push ACR → ssh 两台滚动更新
  bootstrap-node.sh         # ECS 首次初始化（装 docker、建目录、拉代码配置）
  .env.prod.example         # 生产环境变量模板（密钥/内网 IP/ACR 地址）
```

服务 → 节点映射：

| 节点 | 服务（compose profile） | 说明 |
|---|---|---|
| A | mysql redis nacos platform-gateway platform-member nginx | 入口 + 状态 |
| B | family health file platform-reminder | 无状态业务 |

## 3. 自动化发布（本地改动 → 远端最新）

链路：**本地 build+push ACR（镜像 tag=git short sha）→ ssh 到两台执行 pull+up**。

三种触发方式（按成熟度递进）：

1. **一条命令（M1，落地）**：`deploy/release.sh all`——本地构建指定模块镜像、推 ACR、
   SSH 到 A/B 更新。参数化 IMAGE_TAG，支持回滚（`release.sh rollback <tag>`）。
2. **git push 触发（M2）**：backend 加 remote（GitHub/Gitee）后启用
   `.github/workflows/deploy.yml`（已备）：push main → 构建变更模块镜像 → 推 ACR →
   SSH 私钥部署（secrets 存 ACR 凭证与 ECS 私钥）。
3. **本地监听（开发态，可选）**：`fswatch`/`entr` 监听 src 变更跑 release.sh —— 仅自用，
   不进生产流程。

回滚：`IMAGE_TAG=<上一 sha> release.sh all` 即按旧镜像重拉，秒级。

## 4. 微信小程序如何连后端（关键约束）

微信对 request 合法域名的硬性要求：正式发布必须 **HTTPS + ICP 备案域名**。

**当前选定：前期无域名，公网 IP + HTTP 直连（开发态）**——nginx 80 反代已就绪，
小程序构建注入 `VITE_API_BASE=http://<A公网IP>/api`，开发者工具/真机调试勾"不校验合法域名"。
边界：开发版+真机调试可用；体验版需开调试；正式发布再走域名（下方保留）。

| 阶段 | 做法 |
|---|---|
| **前期（当前）** | 公网 IP + HTTP：`VITE_API_BASE=http://<A公网IP>/api npm run build:mp-weixin`，工具勾不校验 |
| 正式（后续） | 备案域名解析到 A → certbot 签 Let's Encrypt → nginx 443 TLS（配置段已预置）→
  重新构建注入 `VITE_API_BASE=https://api.xxx.com/api` |

小程序 BASE_URL 已改造为可注入：`request.ts` 优先读 `VITE_API_BASE`
（`VITE_API_BASE=... npm run build:mp-weixin`），不再硬编码局域网 IP。
上传/下载（file/view、uploadFile）同步走该地址。

## 5. 数据与迁移

- 首次上线：两台 bootstrap 后，在 A 执行 `mysql-init/*.sql`（compose 自动挂载执行 01-19）
- 本地已有数据要上云：`mysqldump star_site | ssh A 'docker exec -i mysql mysql star_site'`
- OSS（可选 M1.5）：开 OSS bucket → `.env.prod` 填 AK/endpoint/bucket → file 服务重启即迁移新上传；
  存量本地文件用 ossutil 一次性迁移

## 6. 上线清单（需要用户提供的）

1. **阿里云 AccessKey**（RAM 子账号，授权 ECS/ACR 读写）→ 我用 CLI 完成安全组/实例核验与引导
2. **域名 + 备案**（生产 HTTPS 硬性要求；未备案前只能开发态 IP 直连）
3. 两台 ECS 的 SSH 登录方式（密码或私钥）→ 写入 deploy 脚本的 ssh 目标
4. （可选）OSS bucket：跨机文件共享

## 7. 风险与对策

- 2G 内存：JVM 已 -Xmx160~192m；再加 1G swap + MySQL `performance_schema=off` 兜底
- 单点：M1 单副本（A 库、B 业务）；M2 可在 B 加 member 副本（nacos 负载），库升级 RDS
- 证书过期：certbot 定时续期 + nginx reload（bootstrap 里带 systemd timer）
- 密钥：.env.prod 不进 git（.gitignore），模板进 git
